How it was run, and a LinuxONE quirk
- On the VM, `trivy image` fails before scanning: "failed to open db: invalid database". The published DB is a
  bbolt file written little-endian (its magic is stored as ed da 0c ed), and bbolt on big-endian s390x reads it
  as the wrong magic. Trivy's s390x binary runs fine; its DB doesn't open there.
- So the SBOM was built on the VM from the real s390x image (`trivy image --format cyclonedx`, which needs no
  vulnerability DB), and matched on the laptop with the same Trivy version (`trivy sbom`).
